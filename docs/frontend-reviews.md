# Отзывы: инструкция для фронтенда

Бэкенд отзывов готов и лежит в `master` (ветки `feature/reviews-core` и `feature/reviews-import`), миграции применены на стенде. Этот документ объясняет, что сделано и зачем, какие есть API и какие экраны нужны. Пользовательские сценарии ниже — отправная точка: продумай их сам, дополни и реализуй. Если что-то неясно или не хватает данных в API — задавай вопросы, бэкенд допилим.

Полный контракт с типами — Swagger: `/api`, JSON — `/api-json` (тег `Reviews`). Доменные подробности — `docs/reviews.md`, решения и их причины — `docs/reviews-plan.md`. Все ответы, как обычно, обёрнуты в `BaseResponseDto` (`responseCode`, `responseValue`).

## Зачем это

1. **Доверие при записи.** Клиент на публичной странице или в виджете видит рейтинг филиала и мастеров и реальные отзывы. Это главный смысл фичи.
2. **Обратная связь бизнесу.** Менеджер видит отзывы, отвечает на них, скрывает спам и оскорбления.
3. **Отзывы на картах.** После отзыва у нас клиенту предлагаем оставить отзыв в Google или Яндекс Картах — бизнесу это нужно для продвижения.
4. **Перенос из другой CRM.** Бизнес, который переходит к нам из YClients и подобных систем, загружает накопленные отзывы из xlsx и не стартует с нулевым рейтингом.

## Как устроено (коротко)

- **Один отзыв на визит.** Оставляет его клиент после завершённого визита, на странице управления записью — по той же ссылке, что и для отмены и переноса. Отдельного логина нет.
- **Оценка 1–5 и обязательный текст** до 2000 символов. HTML сервер вырезает, показывать текст нужно как обычный текст с переносами строк.
- **Мастера подтягиваются из записи сами.** Если в визите было два мастера, один отзыв с одной оценкой засчитывается обоим. Клиент мастеров не выбирает.
- **Отзыв публикуется сразу**, без премодерации. Менеджер может скрыть его (с причиной), ответить на него или удалить.
- **Имя автора** публично показывается маскированным: «Анна К.». Может быть `null` (например, у импортированных отзывов без автора) — тогда показывай «Гость» или подобное.
- **Отзывы можно выключить** для филиала (`reviewsEnabled`). Тогда форма у клиента не появляется, публичные блоки пустые, письма не отправляются.

## Правило показа рейтинга

Сводка везде одинаковая — `ReviewSummaryDto`:

```ts
{
  count: number;            // опубликованные отзывы
  average: number | null;   // один знак после запятой; null, пока отзывов меньше 3
  distribution: { rating: 1 | 2 | 3 | 4 | 5; count: number }[]; // от 5 к 1
}
```

У сотрудника в списках и карточках короткий вариант: `reviewSummary: { count, average } | null`.

| Опубликованных отзывов | Что показывать клиенту |
| --- | --- |
| 0 | Ничего. Не рисовать «0.0» и пустые звёзды, блок отзывов скрыть |
| 1–2 | Список отзывов и «N отзыва». Итоговую оценку не рисовать (`average: null`) |
| 3 и больше | Средняя оценка, количество, распределение |

Фронтенд ничего не вычисляет сам: если `average` равен `null`, звёзды-итог не рисуются. Скрытые отзывы в цифры не входят. В панели управления пустое состояние не скрываем: «Отзывов пока нет» и подсказка, что клиентам после визита уходит письмо с просьбой оценить.

## Права

| Право | Что даёт | По умолчанию |
| --- | --- | --- |
| `review:read` | Раздел отзывов, сводки, отзыв в карточке записи | Владелец, менеджер |
| `review:write` | Скрыть или показать, ответить, удалить | Владелец, менеджер |
| `review.import:write` | Скачать шаблон и импортировать xlsx | Владелец, менеджер |

Права уровня филиала, описаны в `docs/frontend-permissions.json` (группа «Отзывы»). Сотрудники (роль STAFF) отзывов пока не видят — даже своих.

## Сценарий 1. Клиент оставляет отзыв (страница управления записью)

Страница `/booking/manage` по ссылке из писем. Это главный вход: клиенты редко открывают отдельные письма, поэтому форма должна быть видна сразу, вверху страницы, а не за кнопкой или вкладкой.

**Данные** — новые поля в `GET /public/bookings/me`:

| Поле | Смысл |
| --- | --- |
| `canReview: boolean` | Можно создать или изменить отзыв: визит завершён, отзывы у филиала включены, срок не вышел |
| `canReviewUntil: Date \| null` | До какого момента можно оставить или поправить отзыв (конец визита + 14 дней) |
| `review: { rating, text, reviewedAt, reply } \| null` | Свой отзыв клиента. `reply` — `{ text, repliedAt }` ответа бизнеса или `null` |
| `reviewLinks: { google, yandex } \| null` | Ссылки на отзыв в Google и Яндекс Картах. Приходят сразу вместе с формой; `null`, если у филиала ссылок нет |

**Сохранение:** `PUT /public/bookings/me/review`, тело `{ rating: 1..5, text: string }`. Первый вызов создаёт отзыв, следующие — правят его. Ответ — `{ rating, text, reviewedAt, reply }`. Удалить отзыв клиент не может.

**Состояния страницы:**
1. `canReview && !review` → форма: звёзды и текст.
2. После успешного `PUT` → экран «Спасибо». Ссылки на карты уже есть в `reviewLinks` из `GET /public/bookings/me`: для каждой непустой покажи кнопку «Оставить отзыв в Google Картах» / «…в Яндекс Картах». До отправки отзыва ссылки не показываем. После отправки показываем всем, независимо от оценки: Google запрещает просить отзывы только у довольных. Ответ `PUT` — сам отзыв, его можно сразу положить в состояние страницы.
3. `review && canReview` → показать свой отзыв с кнопкой «Изменить» и сроком «можно изменить до …» (`canReviewUntil`).
4. `review && !canReview` → только просмотр.
5. `!canReview && !review` → блока нет. Например, визит ещё не завершён или отзывы выключены.
6. Если у отзыва есть `reply`, показать ответ бизнеса под отзывом.

Если менеджер скрыл отзыв, клиент об этом не узнаёт: свой отзыв он видит как обычно, только ответ бизнеса не показывается.

**Ошибки:**
- `403 / REVIEW_NOT_ALLOWED` — отзыв больше нельзя оставить (срок вышел, отзывы выключили). Перечитай запись.
- `400` — оценка вне 1–5 или пустой текст.
- `401` — ссылка недействительна, как и для остальных действий на странице.

Письмо с просьбой об отзыве уходит само: через 2 часа после завершения визита, если у клиента есть email. Ведёт оно на эту же страницу.

## Сценарий 2. Публичная страница и виджет записи

**Блок отзывов филиала.** В `GET /public/booking-pages/:slug` и `GET /public/booking-widgets/:widgetId` добавлено поле `reviews`:

```ts
reviews: { summary: ReviewSummaryDto; latest: PublicReviewDto[] /* последние 3 */ } | null
```

`null` означает, что отзывы выключены или их ещё нет: блок не рисовать. Иначе показать рейтинг (с учётом правила выше) и три последних отзыва, плюс ссылку «Все отзывы».

**Рейтинг мастера при выборе.** В данных экрана записи (`GET /public/locations/:locationId/booking-setup`, а также `setup` внутри ответа страницы и виджета) у каждого сотрудника есть `reviewSummary: { count, average } | null`. Показывай рядом с мастером звёзды и количество, по тому же правилу.

**Все отзывы:** `GET /public/locations/:locationId/reviews`

| Параметр | Значение |
| --- | --- |
| `page`, `pageSize` | Страница; размер по умолчанию 10, максимум 50 |
| `staffId` | Только отзывы визитов этого мастера — для «отзывы о мастере» |
| `rating` | Только с этой оценкой (фильтр по звёздам) |
| `orderBy` | `reviewedAt` (по умолчанию) или `rating` |
| `orderDirection` | `desc` (по умолчанию) или `asc` |

Ответ: `items`, пагинация (`page`, `pageSize`, `totalItems`, …) и `summary`. С `staffId` сводка считается по мастеру, без него — по филиалу. Фильтр `rating` на сводку не влияет, поэтому распределение можно использовать как кликабельный фильтр по звёздам. `isExport` здесь не работает. Если у филиала выключены отзывы, ответ `404`.

**Элемент отзыва** `PublicReviewDto`:

```ts
{
  id: string;
  authorName: string | null;  // "Анна К." или null → "Гость"
  rating: number;
  text: string;
  reviewedAt: Date;
  reply: { text: string; repliedAt: Date } | null;   // ответ бизнеса
  staff: { id: string; name: string }[];             // мастера визита, может быть пустым
}
```

## Сценарий 3. Раздел «Отзывы» в панели управления

Права: чтение — `review:read`, действия — `review:write`. Все пути относятся к филиалу: `/locations/:locationId/reviews…`.

**Сводка:** `GET /locations/:locationId/reviews/summary[?staffId=]`
→ `{ summary: ReviewSummaryDto, hiddenCount, unansweredCount }`. Сводка считается только по опубликованным отзывам — те же цифры, что видят клиенты. `hiddenCount` — сколько отзывов скрыто, `unansweredCount` — сколько опубликованных ждут ответа. Последнее хорошо смотрится счётчиком или бейджем «Ждут ответа».

**Список:** `GET /locations/:locationId/reviews`

| Параметр | Значение |
| --- | --- |
| `page`, `pageSize`, `isExport` | Как в остальных списках панели |
| `search` | По имени автора, тексту отзыва и тексту ответа |
| `status` | `PUBLISHED` или `HIDDEN` |
| `rating` | 1–5 |
| `staffId` | Отзывы о мастере |
| `clientId` | Отзывы клиента (для карточки клиента) |
| `replied` | `false` — ждут ответа, `true` — с ответом |
| `from`, `to` | Период по дате отзыва (ISO date-time) |
| `orderBy`, `orderDirection` | `reviewedAt` (по умолчанию) или `rating` |

**Отзыв для панели** `ReviewResponseDto`: полное имя автора (`authorFirstName`, `authorLastName`), `rating`, `text`, `reviewedAt`, `status`, `hiddenAt`, `hiddenReason`, `reply: { text, repliedAt, repliedByName } | null`, `staff`, `bookingId` (`null` у импортированных), `clientId`, `source` и даты. `source` — откуда импортирован отзыв, например «YCLIENTS»; у отзывов, оставленных клиентами у нас, он `null`. Его видят только менеджеры.

**Действия:**

| API | Что делает |
| --- | --- |
| `GET /locations/:locationId/reviews/:reviewId` | Один отзыв |
| `PATCH /locations/:locationId/reviews/:reviewId/visibility` | `{ status: 'HIDDEN', reason }` — скрыть, причина обязательна (до 500 символов, клиенту не показывается). `{ status: 'PUBLISHED' }` — вернуть |
| `PUT /locations/:locationId/reviews/:reviewId/reply` | `{ text }` — ответить или изменить ответ (до 2000 символов). Ответ публичный и виден под отзывом |
| `DELETE /locations/:locationId/reviews/:reviewId/reply` | Удалить ответ, `204` |
| `DELETE /locations/:locationId/reviews/:reviewId` | Удалить отзыв навсегда, `204` |

Действия, кроме удаления, возвращают обновлённый `ReviewResponseDto`. Обычный путь для неприемлемого отзыва — **скрыть**. Удаление — исключительный случай (спам, просьба клиента, ошибочный импорт), поэтому нужно подтверждение. Важно для текста подтверждения: после удаления клиент, если его ссылка ещё действует, сможет оставить отзыв заново, а удалённый импортированный отзыв вернётся при повторной загрузке того же файла.

Ошибки: `404 / REVIEW_NOT_FOUND`, `404 / REVIEW_REPLY_NOT_FOUND` (удаление несуществующего ответа), `400 / REVIEW_HIDE_REASON_REQUIRED`.

Все действия пишутся в журнал изменений филиала: новая сущность «Отзыв», события создания, изменения клиентом, смены видимости, ответа, удаления ответа, удаления и импорта.

## Сценарий 4. Отзывы в других карточках панели

- **Карточка записи.** `GET /locations/:locationId/bookings/:id` теперь возвращает поле `review: ReviewResponseDto | null` — отзыв об этом визите, включая скрытый. Поле заполнено только при `review:read`, иначе `null`. Отсюда удобно сразу ответить или скрыть отзыв тем же компонентом, что в разделе отзывов. В списке записей отзыва нет.
- **Карточка и список сотрудников.** У `GET /locations/:locationId/staff`, `GET /locations/:locationId/staff/:id` и `GET /locations/:locationId/staff/directory` есть `reviewSummary: { count, average } | null`. Вкладка «Отзывы» в карточке сотрудника: список с `staffId` и `summary?staffId=` — там есть распределение и счётчики.
- **Карточка клиента.** Отзывы клиента — список с `clientId`. Клиенты принадлежат бренду, а отзывы — филиалу, поэтому запрос идёт по выбранному филиалу.

## Сценарий 5. Настройки филиала

В `GET` и `PUT /locations/:locationId` (те же права, что на остальные настройки филиала) добавлены поля:

| Поле | Смысл |
| --- | --- |
| `reviewsEnabled: boolean` | Собирать ли отзывы. По умолчанию `true`. Выключение прячет форму у клиентов, публичные блоки и рейтинги мастеров и останавливает письма. Уже собранные отзывы не удаляются |
| `googleReviewUrl: string \| null` | Ссылка «оставить отзыв» в Google Картах |
| `yandexReviewUrl: string \| null` | То же для Яндекс Карт |

Ссылки проверяются сервером: только `https`, только «свои» адреса площадки, до 2048 символов. Пустая строка превращается в `null`. Неверная ссылка — `400`.
- Google: `https://g.page/r/<код>/review`, `https://search.google.com/local/writereview?placeid=…`, `https://www.google.com/maps/place/…`. Взять ссылку: Google Business Profile → «Читать отзывы» → «Получить больше отзывов» → «Копировать».
- Яндекс: `https://yandex.ru/maps/org/<название>/<id>/…`, `https://yandex.ru/profile/<id>` (а также домены `.by`, `.kz`, `.uz`, `.com`). Взять ссылку: страница организации на Яндекс Картах, вкладка «Отзывы».
- Короткие ссылки `maps.app.goo.gl` и `goo.gl` не принимаются: они ведут на профиль, а не на форму отзыва.

В форме настроек стоит дать эти подсказки и посоветовать проверить ссылку в приватном окне браузера.

## Сценарий 6. Импорт отзывов из xlsx

Для бизнеса, который переходит из другой CRM. Право `review.import:write`.

| API | Что делает |
| --- | --- |
| `GET /locations/:locationId/reviews/import/template` | Скачать шаблон `reviews-import-template.xlsx`: колонки, строка-пример и лист «Подсказки» |
| `POST /locations/:locationId/reviews/import` | `multipart/form-data`, поле `file`. Валидные строки записываются сразу, предпросмотра нет |

**Файл:** `.xlsx`, до 25 МБ и 50 000 строк, читается первый лист. Обязательные колонки — «Оценка», «Дата», «Текст». Необязательные — «Автор» (или «Имя» + «Фамилия»), «Сотрудник» (можно несколько через запятую), «Источник», «Ответ», «ID». Сервер понимает и английские заголовки. Даты считаются по времени филиала. Полные правила — в `docs/reviews.md`, раздел «Импорт из xlsx», и на листе «Подсказки» шаблона.

**Ответ:**

```ts
{
  totalRows: number;            // непустые строки
  importedCount: number;        // добавлено
  duplicateCount: number;       // уже были загружены раньше или повторяются в файле
  errorCount: number;           // строки с ошибками, пропущены
  unmatchedStaffCount: number;  // имена мастеров, которые не нашлись или неоднозначны
  unmatchedStaffNames: string[];// эти имена как в файле (до 100 уникальных)
  errorsByCode: Record<string, number>; // ошибки по кодам
  errors: { row: number; code: string }[]; // первые 100 ошибок с номерами строк Excel
}
```

Коды ошибок строк: `RATING_INVALID`, `DATE_INVALID`, `TEXT_REQUIRED`, `TEXT_TOO_LONG`, `AUTHOR_TOO_LONG`, `SOURCE_TOO_LONG`, `REPLY_TOO_LONG`, `ID_TOO_LONG`. Нужны понятные русские тексты для каждого.

**Сценарий пользователя:** скачать шаблон → заполнить или подогнать свою выгрузку → загрузить → увидеть отчёт («Загружено 540, уже были 12, с ошибками 3: строка 17 — неверная дата…», «Не нашли мастеров: Ольга, Мария П.») → исправить файл → загрузить снова. Повторная загрузка безопасна: уже принятые строки станут дубликатами и второй раз не добавятся. Отката импорта нет. Ошибочно загруженные отзывы убираются по одному, скрытием или удалением.

Отзыв без найденного мастера остаётся на уровне филиала. Мастер находится по имени, как оно записано в системе: регистр, буква «ё» и лишние пробелы не важны. Если пользователь видит ненайденные имена, он может поправить их в файле и загрузить снова.

Импорт большого файла может занять несколько секунд (до ~10 с на 50 000 строк) — нужен лоадер, и кнопку загрузки на это время стоит заблокировать.

**Ошибки файла:**

| Код | Статус | Что значит |
| --- | --- | --- |
| `REVIEW_IMPORT_FILE_MISSING` | 400 | Файл не передан |
| `REVIEW_IMPORT_FILE_TOO_LARGE` | 413 | Больше 25 МБ |
| `REVIEW_IMPORT_FILE_UNSUPPORTED` | 422 | Не `.xlsx` |
| `REVIEW_IMPORT_FILE_CORRUPT` | 400 | Файл не читается |
| `REVIEW_IMPORT_MISSING_COLUMNS` | 400 | Нет обязательных колонок; в `responseValue` — их ключи: `rating`, `date`, `text` |
| `REVIEW_IMPORT_FILE_EMPTY` | 400 | Под заголовком нет строк |
| `REVIEW_IMPORT_TOO_MANY_ROWS` | 400 | Больше 50 000 строк |

Импортированные отзывы входят в рейтинг как обычные, клиенты их не отличают. Импорт попадает в журнал изменений одной записью: имя файла и счётчики.

## Чего в этой версии нет

- Премодерации нет: отзыв публикуется сразу.
- Сотрудник не видит своих отзывов (это отдельная задача по правам).
- Нет экспорта отзывов в xlsx, виджета на дашборде и уведомления владельцу о плохой оценке — это следующая фаза.
- Нет интеграций с Google, Яндекс и YClients: рейтинг считается только по нашим отзывам.

Список ориентировочный. Предложи свои варианты; если для сценария не хватает данных из API — напиши.

- Компонент звёзд: ввод (форма клиента) и отображение (целые и дробное среднее).
- Единый компонент карточки отзыва для публичных страниц и панели. Варианты для панели: статус «скрыт» с причиной, ответ, действия, источник для импортированных.
- Пустые состояния: публичные (ничего не показывать) и в панели («Отзывов пока нет» + подсказка про письма).
- Форма отзыва у клиента: валидация, редактирование, срок, экран «Спасибо» с кнопками карт.
- Навигация в панели: раздел «Отзывы» филиала, вкладка в карточке сотрудника, блок в карточке записи и клиента, бейдж «Ждут ответа».
- Настройки филиала: переключатель отзывов и поля ссылок с подсказками.
- Импорт: шаблон, загрузка с прогрессом, отчёт с ошибками по строкам и ненайденными мастерами.
- Скрытие элементов по правам (`review:read`, `review:write`, `review.import:write`).
